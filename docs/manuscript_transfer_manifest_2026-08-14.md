## 3. Main theorem statement to transfer

For every integer `m>=1`, use one fixed primitive alphabet

\[
\{0,1,\mathsf{fire},\mathsf{tick}\}
\]

and one-state closed/open grammar schemas independent of `m`. The open grammar adds only the primitive action `fire`.

The same family has

\[
|P_C|=2,
\qquad
|P_O|=2^{m+1},
\qquad
K_O-K_C=m.
\]

The open quotient is discrete on the finite semantic domain, so the memory innovation saturates the finite-domain maximum.

The bounded-local realization simultaneously has:

- constant local state/message alphabets;
- pairwise radius-one dynamics;
- maximum graph degree three;
- tree topology;
- focal/exterior cut width one;
- exact selected-coordinate access length

\[
2\lceil\log_2m\rceil+2.
\]

The local causal-cone lower bound gives `Omega(log m)` selected access in the wider bounded-local class, so the explicit relay is order-optimal in scale.

### Manuscript-safe interpretation

Constant cut width, degree, local alphabets, and one grammar edit do **not** imply a system-size-independent upper bound on the exact open causal interface. A narrow physical boundary is not by itself a small causal boundary.

## 4. Proof order

Use the analytic proof order below rather than the chronological implementation history.

### Step 1 — fixed-contract response quotient

Define legal-word response equivalence for one controlled plant and one declared future grammar. State the exact dynamic-interface characterization through current output, legal-action rows, and successor labels.

### Step 2 — closed invariant

For the extremal family, prove by induction over all closed legal words that no reveal pulse reaches the focal output. The closed trace therefore depends only on the focal bit, giving `|P_C|=2`.

### Step 3 — open coordinate readout

For each exterior coordinate `j`, construct one legal word

\[
w_j=a_j\,\mathsf{fire}\,\mathsf{tick}^{d_j+1}
\]

whose final output recovers that coordinate. Together with the empty word/focal output, these words separate all semantic states, giving `|P_O|=2^(m+1)`.

### Step 4 — maximality

Compare the open quotient with the full finite semantic-domain cardinality and conclude zero capacity slack.

### Step 5 — bounded-local realization

Verify fixed grammar description, bounded local resources, degree three, cut one, arbitrary `m`, and exact query length. Keep architecture-specific constants separate from the generic causal-cone `Omega(log m)` substrate.

### Step 6 — positive boundary

State the conservative macro-schema criterion and the local fiber-split obstruction. If space permits, use the newer exact reuse/converse results only to clarify scope; do not expand the registry theorem count for the first paper.

## 6. Claim slots controlled by H1–H4

Issue #122 is a historical novelty gate, not a theorem-validity gate.

### Outcome A — H1–H4 all verified with comparable overhead

Use wording equivalent to:

> Classical uniform sequential-machine compilation already provides bounded-local realization existence for arbitrary finite source machines under comparable control/timing resources. The CCOC relay is therefore not a first bounded-local existence theorem; its role is an explicit constrained extremal equality witness with fixed grammar, one newly legal action, degree three, cut one, and transparent logarithmic selected access.

Do **not** claim firstness for bounded-local realization existence.

### Outcome B — locality holds but control distribution or latency scales with source state count

The paper may retain a quantitative distinction for the simultaneous fixed-control / degree-three / radius-one / `Theta(log m)` package. State only the exact clause that survives the primary-source comparison.

### Outcome C — only one-way simulation/decoding is established

H3 remains a real gap: a compiler may preserve source behavior while exposing extra observables that split a closed source-equivalence class. Do not treat such a source as automatically reproducing the CCOC closed/open quotient gap.

### Outcome D — incomplete/nondeterministic methods resynthesize hardware

Treat them as strong ancestry for context-dependent decomposition, not the same fixed-hardware grammar-opening construction.
