# RACH asset map: what to mine, what to freeze

This is a routing map, not a deletion list. The repository accumulated several
substantial implementations before its present theorem spine became clear. The
correct response is neither to pretend they are one theory nor to discard them
blindly. Retain each asset for the job it can actually do.

## Rule of classification

An asset is **active core** only if it states or verifies a claim in the
[promotion calculus](promotion_calculus.md). An asset is **gold** if it can make
a future core theorem sharper, falsifiable, or empirically connectable without
changing the theorem's subject. An asset is **frozen infrastructure** when it
preserves proof identity or history without strengthening the causal claim.

## 1. Active core: do new theory work here

| Asset | Current role | Relation to RACH |
|---|---|---|
| `causal_closure_calculus.py` | finite global closure, recurrence, and multistability certificates | promotion across **time** |
| `observation_window_completion.py` | passive-window completion no-go and counterfactual interface inflation | promotion from **inside observation** to **ecosystem outside** |
| `extension_compression.py` | fixed-closed versus open-port lower-bound family | special completion grammar with one focal output and dormant exterior modules |
| `relay_tree_compilation.py` | fixed-grammar, pairwise, degree-three realization | removes the hidden high-degree / global-read objection |
| `observation_regime_closure.py` | exact comparison of two declared action regimes | special operational change of grammar, not the primary inside/outside ontology |
| `current_theory.py` | deliberately small public entrance | only import surface for new theorem work |

The main current claim is:

\[
\text{a rule inside a passive observation window}
\not\Rightarrow
\text{a rule under every allowed exterior completion}.
\]

The core question is not whether the outside literally vanishes. It is whether
it can be omitted or represented by a finite sufficient boundary summary.

## 2. Gold seam A: retained-family and evidence gateway

| Existing asset | Gold that remains | What it must **not** do |
|---|---|---|
| `admissibility.py` | retained-family consensus: a conclusion needs unanimity or becomes `UNRESOLVED` | it must not force completion grammars into the old motif / switch vocabulary |
| `confidence_lifting.py` | lift simultaneous retained-set coverage to a false-decisive bound | it does not establish causal closure or an open interface |
| `anytime_confidence_lifting.py` | all-look / optional-stopping version of retained-set control | it should not become the repository headline |
| `symbolic_candidate_sets.py` | retained families too large to enumerate by hand | solver feasibility is not a proof of outside invariance |
| PR #31 finite-alphabet e-process backend | proof-carrying construction of nested retained candidate sets from data | it is a restricted evidence backend, not the completion theorem |

### Extraction target

Later, extract a generic adapter:

\[
\text{data or solver output}
\to
C_t\text{ of retained completion-grammar candidates}
\to
\text{candidate-safe window/interface verdict}.
\]

The adapter must consume arbitrary candidate-specific completion certificates.
It must not assume floral mechanisms, Boolean motifs, or disjunctive drivers.

**Status:** preserve these modules and PR #31 as evidence-gateway staging. Rebase
or narrow them only when the boundary-completion theorem genuinely needs learned
retained families.

## 3. Gold seam B: counterexample miner and exact proof kernel

| Existing asset | Gold that remains | Future use |
|---|---|---|
| `linear_proof_verifier.py` | exact rational witness and Farkas-certificate checking | verify finite / polyhedral counterexamples to a proposed boundary blanket or preservation claim |
| `rational_polyhedral_inclusion.py` | exact inclusion checks | test whether a proposed sufficient boundary summary actually contains all completion responses |
| `polyhedral_motif_compiler.py` | compiler from restricted semantics to checkable finite query families | reuse only when a new completion theorem genuinely fits its grammar |
| replayable exact-proof modules | content-addressed proof objects | attach a counterexample or finite exhaustion to a theorem, not a new theory layer |
| finite theorem workflows | deterministic enumerative regression pattern | make every new witness replayable and falsifiable |

### Extraction target

Build a small **completion-counterexample protocol**:

```text
proposed boundary / blanket condition
    -> bounded completion grammar search
    -> passive-indistinguishable worlds with a separating future word
    -> independently checked certificate
    -> prove, weaken, or reject the condition
```

This is where the exact-verification machinery creates mathematical value. It
should mine and certify counterexamples; it should not dictate what the theorem
is about.

## 4. Gold seam C: adversarial model laboratory

| Existing asset | Gold that remains | Correct role now |
|---|---|---|
| `ecological_program.py` | grammar for conjunction, inhibition, alternatives, and feasibility restrictions | adversarial source of completion semantics; not the RACH core ontology |
| `failure_modes.py` | counterexamples to hidden compatibility, inhibition, latent routes, and noisy NULL interpretation | red-team tests for every completion or blanket claim |
| `generative_benchmarks.py` | exact finite sweeps rather than Monte Carlo rhetoric | phase diagrams for restricted-theorem failure |
| `observation_envelope.py` | exact channel-induced decision envelopes | test which completions a declared observation channel cannot distinguish |
| `observation_design.py`, `robust_panel_design.py`, `panel_phase_benchmarks.py` | discrete panel selection and non-greedy synergy machinery | later corollary: which new observations or boundary interventions collapse a retained completion family |
| `benchmarks.py` | comparison to known finite truth | regression / calibration harness |

### Extraction target

Turn this layer into a **theorem red-team library**. Test new claims against
small hostile grammars with:

- latent exterior completions;
- compatibility restrictions;
- inhibitory or conjunction-dependent rules;
- simultaneous-message collisions;
- hidden state that breaks a proposed blanket; and
- observation channels that cannot distinguish future-relevant completions.

A failure here is useful: it tells us the theorem needs a sharper boundary.

## 5. Freeze shelf: provenance is not the scientific claim

The following family is technically substantial but should not drive current
research work:

- `certificate_manifest.py`, `tiered_certificate_manifest.py`, and canonical
  JSON variants;
- `admission_transcript.py`, compiled/native transcript variants, and replay
  registries;
- signed transcript checkpoints;
- coverage-contract and transcript adapters; and
- tiered artifact plumbing around those formats.

Their legitimate question is:

\[
\text{Which artifact was used, and has its history changed?}
\]

They do **not** answer:

\[
\text{What outside completion remains possible?}
\quad\text{or}\quad
\text{Does an open ecological law exist?}
\]

**Status:** keep tests passing; add no new provenance feature unless externally
published theorem certificates actually require an audit chain. Do not delete
the code casually: exact-proof assets may still depend on it.

## 6. Compatibility shelf: keep, but do not advertise as core

`causal_model/__init__.py` is a broad backwards-compatible export surface for
older theorem, benchmark, and design modules. It is intentionally not the
research entrance. New theorem work must use `causal_model.current_theory` and
link to this map when it reuses a legacy module.

## Immediate queue

1. **Completion rank lower bound:** formulate a non-circular independence notion
   under which independently addressable exterior completions force additive
   interface memory.
2. **Finite blanket upper bound:** implement and test a controlled boundary
   transducer certificate that proves when an outside can be summarized.
3. **Stabilization criterion:** characterize when an increasing family of
   completion grammars ceases to refine the open-safe quotient.
4. **Counterexample miner:** expose the smallest reusable finite grammar search
   over passive-indistinguishable completions and separating future words.
5. **Evidence bridge only after 1–4:** rebase the e-process work or extract its
   minimal protocol behind generic retained-completion interfaces.
6. **Freeze the audit stack:** no new manifest, transcript, checkpoint, or
   provenance variant without a concrete theorem-publication requirement.

## Anti-queue

Do **not** spend the next cycle on:

- another toy whose only novelty is a larger state table;
- a provenance wrapper around an unchanged theorem;
- a domain-specific floral or ecological model inside this repository;
- a generic statistical backend unconnected to retained completion families; or
- presenting a finite witness as a universal empirical claim.
